# 2026-10-15 — 多 AI 开发协作与变更文档维护流程

本流程把项目结构与修改历史留在仓库中，方便不同 AI 接续开发。根目录 [AGENTS.md](../AGENTS.md) 是规则入口，[开发说明](DEVELOPMENT.md) 是当前实现基线，[文档索引](README.md) 负责连接每次具体改动。

## 1. 获取本次任务所需上下文

先运行 `git status --short`，识别尚未提交的改动。阅读开发说明的项目边界、相关功能章节、代码定位表及对应变更记录，然后用 `rg` 搜索关键符号，定点读取源码和测试。

例如“快速切歌后音量错乱”，优先阅读 `PlaybackStateStore`、Android `PlaybackService` 或 `DesktopPcmPlayer`、相关音量存储和 `PlaybackStateStoreTest`；无需先遍历所有 UI、转换算法和网络客户端。

文档不能替代对本次要修改的代码进行检查。遇到不存在的符号、默认空回调、平台差异、与文档相反的代码或缺失回归时，继续追踪该链路，并在交付时修正文档。大范围迁移或任务跨多个子系统时，可扩大阅读范围。

## 2. 实施与验证

1. 把需求转成可检查的前后行为；Bug 记录复现入口和触发条件。
   - 官网任务从 `website/README.md` 和第 16 节定位，单独验证网站、数据库、手机布局及部署，不套用播放器构建结果。
2. 明确涉及共享代码、Android、Windows 中哪些部分。接口变更检查两端，数据变更检查旧数据和同步包兼容。
3. 实施本次改动，沿用既有状态、协程、存储与 UI 约定，避免顺带重构无关模块。
4. 执行相关测试或人工核对；涉及播放并发、数据持久化、文件转换、删除或同步校验时，需要验证对应边界。
5. 记录实际命令、执行环境、结果和未验证范围。只改文档时核对源码事实、文件链接、旧引用与 diff 即可，无需声称运行了应用测试。
6. 新增变更文档、更新索引和当前开发基线，再交付结果。

## 3. 必须新增的变更文档

文件名规则：

```text
docs/changes/YYYY-MM-DD-NN-简要主题.md
```

`YYYY-MM-DD` 是实际修改日期，使用 Asia/Shanghai；`NN` 是同日递增编号。主题可以用中文或可读英文，不使用“update”“fix”这类无法检索出实际行为的名称。

标题示例：

```markdown
# 2026-10-15 — 修复局域网同步失败后临时包未清理
```

每份文档按 [模板](CHANGE-TEMPLATE.md) 说明：

- 需求或问题的具体表现、触发条件和影响。
- 需要改动的原因；不能确认时标注推测及证据，不能编造根因。
- 实际修改了哪些文件和关键类/函数；每项修改带上目的、行为变化和关联链路。
- 共享代码及两端影响，存储/配置/包格式兼容、权限、网络请求和音频文件影响。
- 实际验证命令及结果；未执行、执行失败或环境受阻要分别说明。
- 已知限制、未完成事项和后续定位入口。

一项功能或修复包含必要的相关调整时可合为一份；同一会话中互相独立的功能/修复各留一份。修正本次尚未交付的记录可以直接编辑；后续再次改变已交付行为时新增记录。历史记录有事实错误时允许勘误并标注日期，不能把新行为伪装成过去已完成。

## 4. 更新哪些现行说明

| 变化 | 必须同步的内容 |
| --- | --- |
| 新增/删除入口、文件移动、职责调整 | 开发说明的目录/模块图和代码定位表 |
| 功能行为、回调接线、平台差异 | 功能链路、能力表、已知缺口 |
| 字段、偏好键、文件格式或缓存变化 | 数据模型、存储及兼容策略 |
| 新外部服务或凭据方式 | 网络边界及第三方组件文档 |
| 依赖、Gradle、构建、测试、发布命令变化 | 环境、命令、测试定位和发布章节 |
| 协作或记录约定变化 | `AGENTS.md`、本流程及模板 |
| 每次交付 | `docs/README.md` 的变更索引 |

开发说明保留当前状态，变更记录保留修改原因和细节；无需在每次记录中复制整份开发说明。开发说明只更新受影响章节，并标明最后核对日期和适用版本；不能只更新日期而不校正内容。

## 5. AI 交接的最小信息

下一位 AI 应能仅凭索引、相关开发说明和变更记录，知道：

1. 目前完成到哪里、哪些行为已经接入、哪些仍是空回调或平台缺口。
2. 从哪几个文件和关键符号继续，哪些数据格式/并发约束不能破坏。
3. 已运行哪些验证，失败或未运行的原因是什么。
4. 当前工作区中哪些改动还没提交，是否存在需要用户补充的信息。

最终交付回复至少给出主要结果、验证状态和新变更文档的路径。没有执行提交、推送、打包或发布时，不得写成已经完成这些动作。

不同 AI 客户端对 `AGENTS.md` 的自动发现能力不同。仓库首页也链接了规则；在不自动读取规则的工具中，将“先读 AGENTS.md 与 docs/README.md，完成后按规则新增变更文档”作为该工具的项目指令。文档约定本身不是能够保证所有工具执行的程序校验器。

## 6. 官网与服务器数据（2026-10-16）

`website/` 与原生播放器隔离。先确认运行目录和数据库，所有发帖、删除、上传、SMTP 回归使用临时库/模拟服务；不要连接用户音频或真实订阅者群发。发布替换只清理官网控制的安装包目录，不清理原工程 `release/`。

真实 `.env`、作者密码散列/私有入口、会话密钥、订阅数据、上传收款码不可进入 Git 或源码部署包。通过 `website/package.py` 明确白名单打包；服务器运行数据和密钥另行备份。修改服务配置后，区分本地浏览器通过、Ubuntu 配置已提供和远程部署/真实邮件尚未验证。
