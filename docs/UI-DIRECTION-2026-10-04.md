# Resonance 当前 UI 方向与天气配色

记录日期：2026-10-04。此文档记录用户在 UI 讨论中确认的偏好，视觉方向优先于旧审阅文档中的深色/珊瑚建议。UI 与天气配色已实施，release APK 已构建；实际运行范围与尚未验证的部分见 [实施报告](UI-IMPLEMENTATION-2026-10-04.md)。

## 已确认的设计方向

- 用户主要直接打开自己创建或导入的歌单，因此首页以真实歌单与封面为主，提供清晰的名称、曲目数和搜索入口。
- 手机优先，浅色调，使用半透明乳白磨砂玻璃、柔和边缘和克制的阴影。文字与封面保持清晰，滚动内容不能因玻璃背景降低可读性。
- 界面不使用橘黄、金色或珊瑚强调色。真实音乐封面的颜色保持原样。
- 用户认可浅灰绿与冰蓝银白两套方案，并希望随天气自动切换。
- 保留 Kotlin Multiplatform / Compose 技术栈和播放、曲库、导入、同步、歌词、设置行为；保持现有深色、浅色、跟随系统的主题选择。天气配色是独立的强调色选项。

## 天气配色规则

| 天气 | 配色 | 说明 |
| --- | --- | --- |
| 晴朗、以晴为主、局部多云 | 浅灰绿 | 乳白玻璃搭配灰绿强调色 |
| 毛毛雨、降雨、冻雨、阵雨、降雪、雨夹雪、雷暴 | 冰蓝银白 | 乳白玻璃搭配冷蓝强调色 |
| 阴天、雾、未知天气 | 保留当前配色 | 首次使用且无缓存时采用浅灰绿 |
| 无网络、定位/天气获取失败、无可用城市 | 保留上次配色 | 不妨碍音乐播放或界面使用 |

天气只改变强调色与表面轻微色调，布局、封面图片与歌词内容不变；深浅主题仍由用户原有设置决定。颜色切换建议约 250–300ms，并在减少动态效果启用时立即切换。

初始色值参考：

| 语义 | 浅灰绿 | 冰蓝银白 |
| --- | --- | --- |
| 浅色背景 | `#F1F6F3` | `#F3F7FB` |
| 主文字 | `#1C302B` | `#172B3A` |
| 强调色 | `#2F7467` | `#315FD0`（实施时为文字对比度加深） |
| 玻璃表面 | 高不透明度乳白、轻灰绿染色 | 高不透明度乳白、轻蓝染色 |

这些是概念图参考值，最终须依据真实界面、各文字大小及背景变化检查对比度。使用语义 token，避免让全部控件直接依赖具体色名。

## 定位与设置

用户已选择：**设备自动定位，定位不可用时以设置中的城市兜底**。

- 天气配色由用户显式开启，开启时说明位置用于获取天气；Android 优先使用大致位置，仅请求前台定位。拒绝权限后仍可使用手动城市或固定配色。
- Windows 尝试平台提供的定位能力；不可用、受系统限制或无权限时使用设置中的城市。实施前检查当前桌面运行环境可用的定位接口。
- 设置提供「天气自动」「固定浅灰绿」「固定冰蓝」以及兜底城市选择。城市需经搜索/选择确认，不能从作者机器、设备时区或示例位置推定。
- 固定配色模式不发起天气定位与天气请求。天气模式在应用前台按缓存有效期更新，建议约 30 分钟；不增加常驻后台定位服务。
- 缓存上次成功的天气代码、配色、更新时间及城市显示信息；天气响应较旧时可以标注更新时间。保存位置时尽量使用城市或粗略坐标，避免记录精确行踪。
- 设置页中的作者机器歌词目录默认值已移除，初始为空，使用自动查找或用户选择目录。

## 天气数据候选与实现边界

已采用 [Open-Meteo 天气 API](https://open-meteo.com/en/docs) 与 [Geocoding API](https://open-meteo.com/en/docs/geocoding-api)。当前天气来自模型数据，因此界面文案使用「当地天气」，避免承诺街道级即时实测。检查时城市搜索成功，天气接口返回 HTTP 429；完整自动切色仍待联网环境复查。

若采用该服务，按其 WMO 天气代码映射：

- 绿色：`0, 1, 2`。
- 蓝色：`51, 53, 55, 56, 57, 61, 63, 65, 66, 67, 71, 73, 75, 77, 80, 81, 82, 85, 86, 95, 96, 97, 99`。
- 保持上次配色：`3, 45, 48` 以及未识别代码。

实施时将天气/定位服务与 UI 分开，给现有主题设置新增独立的配色模式，兼容已有持久化数据。请求失败、过期或重复响应不能使配色反复跳动。最终服务选择及平台定位能力需在实现时核对。
