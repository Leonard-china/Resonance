# 2026-10-17 — 截图截断歌名先核对完整信息，再下载并写入新 MP3 标签

- 修改日期：2026-10-17（Asia/Shanghai）
- 类型：Bug 修复
- 适用版本：0.4.6 / 29
- 影响平台：共享 / Android / Windows
- 关联需求：用户反馈截图里 `XXX...` 的歌名会原样成为下载后的歌曲名称。

## 需求或问题

截图中的长歌名被界面省略。虽然搜索可能找到正确音源，最终曲库和文件标签仍保留省略号。

## 原因与依据

`JvmMusicAssistant.obtain` 用 OCR 的 `SongRequest` 搜索候选后，仍把 `song.title/artist` 原样用于 `VideoImportRequest`。`Mp3Import.arguments`、两端 `importAudio` 都正确执行该请求，因此会把截断文字持久化；搜索命中不代表程序获得了标准曲名。

## 具体修改

| 文件 | 关键符号 | 修改与目的 |
| --- | --- | --- |
| [名称核对](../../composeApp/src/jvmMain/kotlin/com/resonance/player/media/SongIdentityResolver.kt) | `truncated/prefix/matches/choose` | 识别末尾 ASCII/Unicode 省略号；从有歌手匹配的完整名称中选唯一候选；过滤未请求的现场、翻唱等版本，多候选说明原因，不猜写。中间合法省略号不当成截断。 |
| 同上 | `PublicSongMetadataLookup` | 向 QQ音乐/iTunes 查询可见歌名/歌手，支持放宽截断词和歌手查询；18 秒总超时、有界响应、取消断开，失败不冒充成功。 |
| 同上 | `videoNames` | 目录未命中时，仅采用有歌手证据且有书名号或明确歌手分隔的候选名称，不把整条宣传视频标题当歌名。 |
| [导入链路](../../composeApp/src/jvmMain/kotlin/com/resonance/player/features/JvmMusicAssistant.kt) | `obtain/downloadAudio` | 截断输入先核对本地曲库和公开信息，确认后再搜索音源；完整请求统一进入转码/标签/曲库/歌单。重遇同一已导入视频时只修正原截断库覆盖值和成员快照，不重复下载或重编码旧音频。 |
| 名称核对与音源查询 | `searchTitle` | 仅在音源检索时去除括号中的 feat./ft./featuring 信息；显示及新 MP3 标签保留完整标准曲名，避免附加艺人信息导致精确音源匹配失败。 |

## 修改前后行为

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 可确认完整名称的 `Long Song...` | 以截断名称下载和写标签 | 新 MP3 标签、曲库和歌单都保存完整名称。 |
| 多个可能曲名 | 搜索评分首选后直接下载 | 列出候选及未完成原因，要求补足信息。 |
| 正常完整歌名 | 原搜索/导入 | 保留，不为每首增加目录查询。 |

## 平台与数据影响

本地 OCR / 云端 API 共用修复。查询只发送可见歌曲文本，不上传截图/音频，不增加收费模型调用。没有批量改名历史歌曲，没有改写用户外部音频；新下载 MP3 标签按确认信息写入。重新导入已有视频的旧 MP3 标签不因此重新编码/写回，只更新曲库显示与歌单快照。

## 验证

新增回归检查前缀/歌手/版本匹配、歧义拒绝、正常中间省略号保留，并通过注入的目录结果验证从本地截图到下载、曲库、歌单的完整命名及含 feat. 曲名的音源查询。最终 `:composeApp:allTests` 共 131 项通过，0 失败。

实际打包客户端的公共目录探测成功将 `说好的幸... / 周杰伦` 核对为 `说好的幸福呢`，将 `See You Ag... / Wiz Khalifa` 核对为 `See You Again`。实际打包 FFmpeg 与 `Mp3Import` 生成合成音频 MP3，再用 jaudiotagger 读回，完整 Unicode 标题一致；没有下载用户歌曲或改写现有文件。最终命令和实际结果见 [发布与验证](2026-10-17-03-release-0.4.6.md)。

## 限制与后续

隐藏文字不在截图中，必须由真实检索证据补足。目录覆盖率、服务访问限制和不同艺名写法可能导致无法确认；这种情况明确报告，不保证所有曲目自动补全。未使用用户账号/付费 Key 做线上服务实测。
