# 2026-10-17 — 构建并发布 Resonance v0.4.6 本地 OCR 双端正式版

- 修改日期：2026-10-17（Asia/Shanghai）
- 类型：构建 / 发布 / 生产运维
- 适用版本：0.4.5 / 28 → 0.4.6 / 29
- 影响平台：Android / Windows / GitHub / 独立官网
- 关联需求：用户明确要求本地 OCR 与完整歌名修复完成后构建新版，推送 GitHub、官网，并发布官网更新公告和软件介绍。

## 需求或问题

将本次两端功能以正式安装包交付；不能只更新版本文本、沿用旧产物或把本地测试当成生产发布。

## 原因与依据

版本唯一来源 `version.properties`，本次显式升版；模型需要实际进入 APK 与 Windows 资源，且 Windows 的 ONNX 1.21.1 / 1.23.2 Java 原生库在本机出现 DLL 初始化失败。独立探测验证 1.20.0 可加载，因此 Windows 使用 1.20.0 CPU，Android 使用 1.23.2；没有删除或替换系统/JDK DLL。

### 实际失败与修正

- 首轮编译错误：ONNX FloatBuffer API 使用错误，修正后定点构建通过。
- 首轮定点回归有 3 项失败：Windows ONNX 原生库无法初始化、旧缓存测试使用了不同备注却仍期待缓存命中，以及构建期间源码变动导致标题测试与旧编译结果不一致。选择经加载验证的 Windows 运行时、按新缓存语义修正用例并重新构建后，25 项通过；保留 `build/ocr/compile.log`、`targeted-tests.log`，不把失败结果算通过。
- Windows Release ProGuard 首次对 ONNX 的 `Fp16Conversions` MethodHandle 特殊签名产生警告；仅对该类添加精确 `dontwarn`，未扩大为全局忽略。实际 FP32 模型加载与 OCR 均通过，最终完整正式构建成功。
- 公开目录早期探测的酷狗接口返回签名错误，未作为补全依据；本次最终新增补全走 QQ音乐/iTunes，经真实中英文目录查询验证。
