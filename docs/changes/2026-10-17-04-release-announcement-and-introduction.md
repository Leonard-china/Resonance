# 2026-10-17 — 官网按已发布版本更新公告与 Resonance 详细软件介绍

- 修改日期：2026-10-17（Asia/Shanghai）
- 类型：官网内容 / 发布工具
- 适用版本：0.4.6 / 29
- 影响平台：独立官网 `website/`
- 关联需求：完成播放器新版后，在官网发布新的更新公告和软件介绍。

## 需求或问题

需要将真实发布功能、识图切换与网络边界同步给官网访客，避免只更新安装包、公告仍介绍旧版。

## 原因与依据

论坛公告来自 SQLite `settings.announcement_title/announcement_body`，直接改默认常量不能覆盖现网已存在的公告。更新还需发生在相应双端安装包发布成功之后。

## 具体修改

| 文件 | 关键符号 | 修改与目的 |
| --- | --- | --- |
| [已审核内容](../../website/content/0.4.6.json) | `version/title/body` | 包含 v0.4.6 更新、本地 OCR 与 API/联网边界、完整歌名核对、播放器定位/曲库/转换/歌词/助手/推荐/教程介绍。 |
| [公告发布](../../website/announcements.py) | `publish_announcement` | 校验版本、标题/正文长度，只有对应版本为当前正式下载时，才在单一事务更新公告两项设置。 |
| [命令行](../../website/manage.py) | `publish-announcement` | 提供可复现的已审核文件发布命令；与安装包发布、邮件发送分开。 |
| [部署包](../../website/package.py) | 白名单 | 包含新模块与公开内容目录，不加入运行数据/密钥。 |
| [回归](../../website/tests/test_announcements.py) | 临时库 | 核对正确版本发布、版本不符/正文无效保留旧公告、不创建邮件任务和内容边界。 |

## 修改前后行为

公告从旧版功能介绍切换到带日期的 v0.4.6 更新与完整软件介绍。首页原公告跳转继续通向 `/forum#announcement`。不新增真实订阅者邮件，不删除或修改论坛帖子。

## 平台与数据影响

只更新独立官网公共内容和运维命令，不连接播放器音乐库。真实数据库先在服务器做在线备份；只写两项公告设置，保留作者配置、订阅、上传图和当前安装包。公开内容不含后台入口、凭据或运维认证信息。

## 验证

最终工作区执行 `python -m unittest discover -s website/tests -v`，42 项通过；独立导出暂存区源码执行同一测试，38 项通过，验证本次提交不依赖用户既有未提交官网改动。两组测试均不调用真实 SMTP。实际生产发布与页面核对结果见 [本次发布记录](2026-10-17-03-release-0.4.6.md)。

2026-10-17 实际生产调用 `publish_announcement` 成功，当前正式下载版本为 0.4.6。重启网站后，公开 HTTPS [论坛公告](https://leonard.asia/forum#announcement) 返回 200 / `no-store`，实际正文包含新版本机 OCR 说明与“Resonance 是什么”等完整软件介绍；首页和下载页同样返回 200，并展示本次正式版本及安装包信息。没有将上传内容文件成功替代为生效判断。

## 限制与后续

实际生产结果以发布记录为准；不把静态内容文件存在或上传成功当成公告已经生效。修改现网公告后，已打开页面的内存导航缓存可能在其既有 3 分钟有效期内仍显示旧内容，重新加载会读取当前公告。
