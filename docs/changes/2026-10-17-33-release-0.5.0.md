在完成本轮 9 项核心体验优化与 Lint 代码合规修复后，按规范升版至 `0.5.0 / 33`。执行全量自动化测试（`allTests`）、Android Release 代码分析（`lintRelease`）、官方签名 APK 打包（`assembleRelease`）与 Windows 安装包制作（`packageReleaseExe`），并安全部署至生产服务器 `leonard.asia`（翼龙容器 + Cloudflare Tunnel），同步更新官方下载页面与社区公告。

## 原因与依据

1. **版本规范**：依据 `AGENTS.md`，版本号以 `version.properties` 为唯一来源，正式发布时显式更新：`versionName=0.5.0`，`versionCode=33`。
2. **全流程自动化构建与校验**：通过 `scripts\build.ps1 -NoBump` 自动化执行全量测试套件、Release Lint、Android 签名打包与 Windows EXE 打包，并调用 `scripts/release-manifest.ps1` 收集二进制至 `release/0.5.0/`，实时计算 SHA-256 并回填至 `docs/RELEASE_NOTES-0.5.0.md`。
3. **版本更新特性提取**：Gradle `generateAppVersion` 自动读取 `docs/RELEASE_NOTES-0.5.0.md` 中的“## 主要更新”条目生成 `BuildVersion.kt`，通过 `HorizontalPageSwipeUnitTest` 断言版本号、发布日期与 9 项更新条目全部匹配。
4. **受控生产发布**：依据 `website/OPERATIONS.md`，部署前在远端执行 SQLite 在线备份（`con.backup(bkp)`）与代码备份；通过受控 `releases.publish` 事务原子切换两端安装包并校验魔数与哈希；通过 `publish_announcement` 发布对应版本公告；重启 Gunicorn 容器并核验 HTTP Range 下载、魔数、哈希与缓存状态。

- **跨平台共享**：`BuildVersion.kt` 自动更新版本常量，两端代码行为一致。
- **Android 端**：由官方发布证书签名打包 `Resonance-0.5.0-release.apk`，支持从旧版本平滑覆盖安装，完全保留曲库数据、自建歌单与偏好设置。
- **Windows 端**：由 Compose Desktop 打包完整可分发运行环境 `Resonance-0.5.0.exe`，集成 JRE 运行时与 FFmpeg。
- **数据兼容性**：任务分组、离线状态标记、推荐历史反馈、睡眠定时与网络偏好完全向下兼容历史数据。

## 限制与后续

1. **真实物理设备回归**：因宿主机未连接 Android 硬件手机或运行模拟器，Instrumentation 视觉插桩测试未在真机执行（双端编译、静态分析与全量单元测试已通过）。
2. **Cloudflare 边缘缓存**：公开展示页 `/downloads` 配置了 2 小时 Edge TTL 强缓存。全球部分 Anycast 节点在缓存未过期前可能返回旧缓存页面；如需全网即刻同步展示，可在 Cloudflare 控制台执行 `Purge Everything` 或等待 TTL 自动回源。
