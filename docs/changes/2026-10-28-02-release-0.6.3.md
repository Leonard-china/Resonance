## 需求或问题

1. 播放器近期完成了多项重大核心特性升级：
   - 听歌时长与完播次数精准统计、原子文件持久化及在歌曲来源与六维品味画像中的高亮呈现；
   - 7 大跨平台 PCM 专业音效预设（原声直通、纯净人声、澎湃动态低音、现场流行、震撼摇滚、3D环绕声场空间扩展与 K 歌伴奏消音）；
   - 全面解除 AI 音乐助手单月 Token 消耗上限、余额预算拦截及输入截断限制；
   - 每日推荐歌曲新增未听保护机制（到期若有推荐歌曲未收听，自动保留现有推荐不予强制覆盖）；
   - 取消 AI 助手 16 轮工具调用步数硬编码上限，支持长链路 Agent 自主完成曲库深度分析与调度；
   - 温润雅致质感打磨、标志性波浪动态进度条与沉浸光晕动效。
2. 需要将上述所有功能统一集成，递增版本至 `0.6.3 / 37`，完成双端 Release 构建（Android Release APK 与 Windows Release EXE），生成严格可复现的 SHA-256 校验和并回填发布说明。
3. 将本次发布包与 Release Notes 发布至 GitHub Releases（创建 `v0.6.3` 标签并附带真实双端二进制文件与校验清单）。
4. 将最新版本信息、下载通道与更新公告同步部署至官网（`leonard.asia`），完成现网数据库切换与平滑生效。

## 原因与依据

1. 遵循仓库核心协作规范 [`AGENTS.md`](../../AGENTS.md)：
   - 版本唯一来源严格为 `version.properties`，由 `0.6.2 / 36` 升版至 `0.6.3 / 37`；
   - 不手写生成的 `BuildVersion.kt`，由 Gradle `generateAppVersion` 任务解析 `version.properties` 与 `docs/RELEASE_NOTES-0.6.3.md` 自动生成；
   - 产物校验值必须从本次实际产物计算生成，严禁复用旧值；
   - 官网部署遵循 `website/README.md` 与 `website/OPERATIONS.md`，保持真实运行数据、会话密钥与私钥隔离。
2. 自动化构建管线：
   - 执行 `scripts/build.ps1 -NoBump`，自动调用 `:composeApp:allTests`、`:composeApp:lintRelease`、`:composeApp:assembleRelease` 与 `:composeApp:packageReleaseExe`；
   - 执行 `scripts/release-manifest.ps1 -Version 0.6.3`，将产物收敛至 `release/0.6.3/`，写入 `SHA256SUMS.txt` 并自动替换 `docs/RELEASE_NOTES-0.6.3.md` 中的 `<!-- GENERATED-CHECKSUMS -->` 表格。
3. 官网与公告发布：
   - 依据 `website/announcements.py` 与 `website/releases.py`，官网发布采用 SQLite 事务将最新版本信息与产物摘要（大小、SHA-256）写入 `releases` 与 `assets` 表，更新 `active_release` 键；
   - 同步 `website/content/0.6.3.json`，通过 `manage.py publish-announcement` 发布官方更新公告。

## 平台与数据影响

- **跨平台共享**：`BuildVersion.kt` 自动更新版本常量；听歌时长与音效状态通过跨平台服务契约统一管理。
- **Android**：生成最终签名的 `Resonance-0.6.3-release.apk`（159.14 MiB），包含完整 Media3 音频管线、PreampAudioProcessor 预设与后台服务。
- **Windows**：生成最终分发的 `Resonance-0.6.3.exe`（306.48 MiB），内置 JRE 运行时与 DesktopPcmPlayer 滤镜调优。
- **数据兼容性**：新版本平滑兼容现有所有本地曲库、自建歌单、AI 语义找歌模型、品味画像、`listening-stats.json` 及 `audio-features.json`，无破坏性迁移。
- **官网现网**：更新官网 SQLite 数据库与公告，提供 GitHub 镜像直链与官网备用下载，全网 CDN 边缘缓存自动支持。
