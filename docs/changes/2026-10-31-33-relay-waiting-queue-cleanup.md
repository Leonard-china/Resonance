# 2026-10-31 — 修正中继等待队列清理与房间上限

- 修改日期：2026-10-31（Asia/Shanghai）
- 类型：可选中继并发与资源边界修复；版本 0.6.5 / 39，不升版
- 影响平台：用户自行运行的独立 Python 中继服务
- 关联：[中继初始实现](2026-10-31-20-opt-in-encrypted-relay-transport.md)、[多人等待队列](2026-10-31-23-multiplayer-room-coordinator-and-equal-control.md)

## 需求或问题

多位访客通过自选中继进入时，已有连接收尾不应删除同一路由后续新建的等待队列；房间数量超过限制也不应遗留空路由耗尽服务容量。

## 原因与依据

静态检查 `Relay.handle`：先前 `setdefault` 在检查容量前插入空列表，超限返回时没有对应清理；旧列表被访客取空后，新主机可能在相同路由建立新列表，旧主机的 `finally` 会按相同键误删新列表。已超时的等待 Future 也不能再接受 `set_result`。

## 具体修改

| 文件 | 符号 | 修改 |
| --- | --- | --- |
| [server.py](../../services/relay/server.py) | `Relay.handle` | 在添加新路由前检查上限；仅在字典中的当前列表仍是本次列表时删除空路由；访客匹配时跳过已完成或取消的等待 Future |

## 修改前后行为

源码设计上，旧等待队列结束不会清理同键的后续队列；达到路由上限不会再创建空项；无有效等待连接时向访客返回不可用。不会改变 TLS 字节转发格式和用户的配置。

## 平台与数据影响

只涉及用户自行选择和运行的中继内存状态，不部署公共服务、不读取聊天或音频内容，也不更改 Android/Windows 本地数据。

## 验证

仅静态阅读 Python 协程的共享字典和等待生命周期；遵循用户要求未启动服务、构建或测试。未进行压力、故障注入、安全或真实跨网验证。

## 限制与后续

客户端多人恢复路由仍待修复；服务的生产级防滥用、运维、恶意输入、等待/取消竞态和端到端安全均须进一步审查及验收。
