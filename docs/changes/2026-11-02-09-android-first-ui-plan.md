## 需求或问题

本次交付完整设计与实施顺序，不实施产品代码。目标是让手机上的找歌、播放、看歌词、与朋友一起听更直接，同时统一助手、工具、设置和弹窗的视觉与操作。

推荐方向：**专辑封面主导的现代原生音乐播放器**。沿用已有石墨深色、雾白浅色与波浪进度条，把视觉表达集中在音乐内容和播放器；常规浏览、聊天和设置保持清晰、稳定的层级。

## 具体修改

本次实际只新增此方案，并在 [docs/README.md](../README.md) 增加入口和索引。以下所有产品行为均为建议，等待进入实施阶段。

### 1. 信息架构与手机导航

推荐四个一级目的地，所有窗口保持相同顺序：

| 目的地 | 首要任务 | 页面结构 |
| --- | --- | --- |
| 音乐库 | 找到并播放自己的音乐 | 搜索入口；歌曲/歌单/专辑/歌手；收藏、每日推荐；与当前内容相关的操作 |
| 助手 | 描述想听的内容、导入截图、整理音乐 | 对话与结果；底部输入；历史和设置收纳到菜单 |
| 一起听 | 创建或加入房间、回到正在进行的房间 | 空闲、连接中、房间中三个明确阶段 |
| 工具 | 管理音乐与偏好 | 音乐管理、聆听记录、应用设置三个分组 |

搜索仍复用已有本地/在线能力，默认本地；在搜索页明确切换范围。歌曲页的即时过滤改成有状态提示的筛选入口，避免两个相似输入框让用户分不清范围。每日推荐沿用现有开启/关闭和未听保护逻辑，入口与收藏并列、视觉从属曲库。

手机主壳：内容区 → MiniPlayer → NavigationBar。MiniPlayer 显示封面、歌曲、播放/暂停和下一首，点击展开播放器；明确标识一起听房间播放。助手未输入时保留 MiniPlayer，键盘出现时隐藏底栏与 MiniPlayer；房间页已有固定播放区时不重复呈现。

返回优先处理键盘、最上层浮层和当前详情，再返回所属一级页。切换目的地后保留各自的滚动位置、搜索条件和合理的草稿状态；凭据与邀请内容不自动进入 SavedState。

### 2. 核心页面改法

| 页面 | 布局与交互方案 | 验收重点 |
| --- | --- | --- |
| 曲库 | 顶部标题与搜索/更多；歌曲标签下为紧凑的数量、排序和筛选栏；歌曲行统一为封面、标题、艺人、状态和更多 | 手机上首屏内容优先；长标题不挤掉操作；正在播放和不可播放状态易区分 |
| 歌单/专辑/歌手详情 | 可折叠封面信息；主要播放操作；歌曲列表；编辑收进上下文菜单 | 滚动后仍容易播放；返回原列表保持位置；歌单新建和添加音乐路径明确 |
| 完整播放器 | 顶部仅保留收起、上下文和更多；中间封面与歌曲信息；下部固定进度和控制；封面/歌词/队列切换靠近底部 | 去掉顶部重复歌名；短屏/大字号先收缩封面、留白和歌词预览，保证播放控制可达 |
| 歌词 | 独立阅读区；当前行突出、上下文保持可读；译文次级；歌词工具以底部面板展开 | 保留手动浏览、回到当前行和点击跳转；翻译中/失败/重试位置稳定 |
| 队列 | 正在播放分区、后续队列、下一首标记；行内菜单管理；排序同时提供可访问的移动操作 | 正在播放位置明确；大队列不卡顿；清空与单曲移除语义清楚 |
| 音乐助手 | 一行顶栏；新对话、历史、设置进入清晰菜单；任务运行时出现可展开状态条；示例缩为紧凑入口 | 键盘弹出后最新消息与输入框可见；任务进度不会挤没对话；示例仍只填草稿 |
| 一起听首页 | 创建房间为主按钮、加入朋友为次按钮；已有伙伴位于下方；连接细节进入高级设置 | 新用户能直接开始；普通错误就地解释并重试；保留现有自动连接流程 |
| 一起听房间 | 顶部成员与连接状态；中间聊天/队列切换；下方固定当前歌曲和控制；邀请、成员管理可展开 | 看得到谁在听和当前歌曲；聊天输入不遮挡；离开房间需清晰表达后果 |
| 工具与设置 | 工具按任务分组；设置分为外观、播放与音效、歌词、音乐库与存储、助手与歌源、帮助与关于 | 第一屏能找到类别；即时开关不额外要求保存；需要提交的表单明确保存状态 |
| 导入/下载/任务 | 展示总体进度和当前步骤；失败原因、取消和安全重试靠近任务；批量操作给出数量 | 扫描、转换、下载状态可区分；失败保留已完成内容；收费请求继续按原边界处理 |
| 品味画像/统计/智能管家 | 统一标题、数据字阶和图表标注；首屏呈现关键结果，解释与更多操作下沉 | 图表有文本说明；建议与实际操作分离；删除音频与仅移出歌单文案不同 |
| 首次使用/空态 | 空曲库突出“导入本地音乐”，提供搜索入口；教程作为可继续的帮助 | 不要求先完成长教程才能听歌；无歌曲、无结果、权限未授予给出对应下一步 |

### 3. 统一视觉规范

延续当前已实现的中性色板，形成以下语义角色；颜色集中在主题层，页面只引用角色。

| 语义角色 | 深色基线 | 浅色基线 | 用途 |
| --- | --- | --- | --- |
| Canvas | `#101114` | `#F3F4F6` | 页面画布 |
| Surface | `#191B20` | `#FFFFFF` | 面板与浮层 |
| SurfaceVariant | `#24272E` | `#E8EBEF` | 选项分组、次级容器 |
| OnSurface | `#F1F3F5` | `#20252D` | 主文字 |
| OnSurfaceVariant | `#ADB3BE` | `#536171` | 次级文字 |
| Primary | `#CCD2DB` | `#465366` | 主要操作与选中状态，必须配套 OnPrimary |

保留 IceBlue、系统主题和天气偏好。封面取色用于播放器局部背景，文字/按钮由可读的主题表面承载，避免随专辑颜色改变文字对比度。常规列表使用实色；轻量材质仅用于播放控制和必要浮层。

字阶建议：手机页标题 24–28sp、歌曲标题 16sp、正文 14–16sp、辅助说明 12–14sp；这些是本项目候选设计值，实际复用并校准 Typography。使用系统无衬线字体，优先中文可读性。除封面与播放器控制外，信息以左对齐为主。

间距采用 4/8/12/16/24/32dp；手机左右边距以 16–20dp 为起点。圆角按用途分为小封面/输入控件、内容面板、底部浮层，避免所有控件同样圆、同样重阴影。统一图标尺寸、文字基线、按钮层级、开关和设置行；先做可复用组件，再替换页面。

### 4. Android 自适应与可访问性

- 先验收 360/393/412dp 手机竖屏，再覆盖 320dp 极窄窗、640×360dp 横屏、600/840dp 附近分屏和折叠窗口。候选宽度分级为 `<600dp` 手机底栏、`600–839dp` 导航轨、`≥840dp` 在内容适合时采用双栏；不能仅按宽度忽略高度和字号。参考 [Android 窗口大小类别](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes)。
- 同时验证 1.0/1.3/1.5/2.0 倍字体。两倍字体允许内容区滚动和减少装饰信息，核心播放、返回、提交操作不能消失。
- 交互热区至少 48×48dp；图标视觉尺寸可较小。自定义波浪进度、播放按钮、切换器提供角色、名称、状态和调整语义。参考 [Compose 可访问性默认行为](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)。
- 对主题组合、封面背景和禁用/选中/错误状态分别测量对比度；采用普通文字 4.5:1、重要图形和大文字 3:1 的项目验收目标，不靠颜色单独传达状态。
- 验证手势导航、三键导航、挖孔、状态栏、键盘和底部面板的 Insets，防止重复留白或遮挡。参考 [Compose Insets](https://developer.android.com/develop/ui/compose/system/insets-ui)。
- 验证系统返回/预测性返回与播放器下拉收起、歌词滚动、队列拖动之间的冲突；所有手势都保留可见按钮替代。
- 旋转、分屏、Activity 重建后保持播放、所在目的地、列表位置与安全的用户输入。扩展现有恢复能力，不能只检查目的地枚举。
- 平板/Windows 在后续阶段使用列表与详情、封面与歌词的并排空间，并验证键盘焦点与鼠标操作。多栏若需要导航框架迁移，单独评估 Navigation 3 及跨平台兼容性，不把迁移设为首批手机优化的前置条件。

### 5. 反馈与动效

每类公共组件覆盖默认、按下、选中、禁用、加载、失败、空态；Windows 另有焦点和悬停。加载不清空旧内容；失败就地显示原因和重试；搜索无结果保留查询条件。沿用已经接入的准备/缓冲真实状态，错误反馈不改成无条件成功提示。

建议按压约 100–120ms、普通状态约 160–200ms、播放器展开约 220–280ms，最终以真机感受和帧数据调整。降低高频切页的明显过冲，把回弹留给直接拖拽等有物理含义的交互。保留波浪进度和封面氛围，但暂停、后台及减少动态效果时停止装饰运动；遵循系统动效设置与应用偏好。

Android 性能验证使用同一设备、同一测试数据、相同构建类型的前后对照，分别测冷启动导航、预热切页、长曲库滚动、播放器/歌词和键盘展开。观察 p95 帧耗时及超帧预算比例；不能把历史 MuMu 数据或离屏截图当成本次流畅度结论。

### 6. 分批实施与交付

| 批次 | 范围与顺序 | 可检查交付物 | 主要源码入口 |
| --- | --- | --- | --- |
| 第一批：日常听歌 | 固定手机基线 → 公共视觉组件 → 四项导航与 MiniPlayer → 曲库/详情 → 播放器/歌词/队列 | 360/393dp 深浅主题原生前后图；完整找歌到播放流程；大字/短屏操作检查 | `ResonanceTheme`、`GallerySurfaces`、`AccessibleIconButton`、`LibraryShell`、`PlaylistGrid`、`NowPlayingOverlay`、`SoftNeumorphicButtons` |
| 第二批：完整体验 | 助手 → 一起听 → 工具/分类设置 → 导入/任务/搜索/画像 → 全部弹窗与状态 | 手机所有主要页面风格一致；键盘/输入/错误恢复检查；按功能独立变更记录 | `MusicFeatureScreens`、`TogetherScreen`、`TogetherCompanionPanel`、`ToolsScreens`、`AppearanceSettings`、`MusicTasksScreen`、各 Dialog |
| 第三批：适配收尾 | Android 系统集成、TalkBack、旋转/分屏、性能 → 平板/Windows 同步整理 | 同设备帧数据对照；原生设备回归；桌面功能与输入回归；剩余限制清单 | `MainActivity`、平台 BackHandler/SystemBars、现有 UI/设备测试 |

第一批先把曲库和播放器做成可评价的原生样板，再扩展同一规范。每批都执行基本适配与功能验证；第三批是全面矩阵验收，不能把前两批的可用性问题全部推迟到最后。

修改共享主题时先检查全部引用，避免 Android 优化导致 Windows 退化；单次只提取服务当前改动的组件，保持播放、持久化和房间状态边界。

计划复用并补充以下回归：`UiVisualContractTest`、`LibraryNavigationTest`、`LibraryDetailTransitionTest`、`MusicStageDeviceTest`、`TogetherUiDeviceTest`、`TutorialNavigationTest`、`MusicStageFrameMetricsTest`。界面变更不能使原有教程锚点、测试语义和可访问名称失效。涉及新状态和交互时新增有行为意义的用例，截图同时检查实际内容与操作可达性。

验收路径至少包括：首次导入→找到歌曲→播放；搜索→详情→返回原列表；播放→歌词→队列；助手输入→运行任务→查看结果；创建/加入房间→聊天→播放控制→离开；深浅主题切换与重启恢复。性能结论必须来自本轮实际测量。
