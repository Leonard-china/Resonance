# 2026-11-05 — 安装 Linux 歌词修复版并准备手机正式覆盖包

- 修改日期：2026-11-05（Asia/Shanghai）
- 类型：本机正式安装 / 构建 / 验证
- 适用版本：0.6.6 / 40；不升版
- 影响平台：当前 Android 手机、Linux x86_64 电脑
- 关联需求：用户明确要求“替换我手机和电脑上现在装的”。
- 关联修复：[恢复封面歌词、同步优先与高亮](2026-11-05-08-restore-player-lyrics-and-synchronized-priority.md)。

## 需求或问题

前轮歌词修复只完成源码、独立 Debug 验证包和回归，日常手机与电脑仍运行旧安装。本轮要求将修复真正安装到原应用入口，保留既有歌曲、歌单、设置和旧程序回退副本。

## 原因与依据

安装前核对手机正式包名 `com.resonance.player`，版本为 0.6.6 / 40；电脑 `current` 和正在运行的可执行程序均来自 `0.6.6-20261105-stability-refactor/`。相同版本号不能说明二进制已经包含新修复，因此需要完整重编译、核对本次产物并验证实际安装和运行路径。

本轮不增加业务源码改动，不修改版本、权限、曲库/歌单/歌词/配置格式、播放后端或同步协议。手机使用覆盖更新，电脑仅复制程序、切换安装链接和正常重启；不删除/重写用户音频、导出包或元数据。签名通过既有构建配置使用，不读取或输出真实签名配置、私钥或用户 API Key。

不涉及 Windows 安装、官网/GitHub 发布和服务器部署。Linux 本机使用普通完整 app image，不将其称为 ProGuard Release 包。

## 验证

全部重量级步骤串行，以独立 systemd 用户服务将整个进程树限制为 MemoryMax=2G、MemoryHigh=1536M、MemorySwapMax=0；单 worker、短生命周期 Gradle、进程内 Kotlin 策略。日志与源文件 SHA-256 清单位于上述忽略目录。

| 实际命令或操作 | 环境 | 结果 |
| --- | --- | --- |
| 导出 `compileReleaseKotlinAndroid` / `compileKotlinDesktop` 实际类路径，完整 CLI 编译 | 当前 Kotlin/Compose compiler 2.3.20、JDK 17 | 通过：正式 Android 主源码 189 个（不含 Debug 测试宿主）、桌面主源码 198 个；保存全量源文件 SHA-256，安装时再次核对仍与当前源码一致。 |

Android 中间候选包的首次独立 DEX 合并脚本只收集 `.dex`，漏掉项目 DEX 目录中的资源 `.jar`（内含 `classes.dex`），导致实际启动时缺少 `androidx.startup.R$string`。启动命令虽返回 `ok`，后续进程复核发现初始化异常，因此该候选不计作启动通过，并立即用保存的原签名 APK 进行 `install -r` 回退，保留数据；随后补齐归档输入，并增加全部输入类定义和资源类校验、APK 中每份 DEX 与完整合并结果逐字节核对，以及安装后连续观察进程和恢复 Activity 的检查。原有 AndroidX 初始化器和业务源码保持，实际修正为输入归档收集与完整性检查。中间失败记录单独保存在 `phone-install-first-candidate-failed.json`，最终结果以之后的完整包验收为准。

电脑的初次探针在窗口仍在创建时采样，后续窗口处于最小化状态；最终恢复窗口并重新核对才记为可见通过。安装脚本及探针只放在忽略目录，不进入产品包。
