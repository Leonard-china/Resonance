# 2026-11-13 — 将歌曲菜单中的歌单操作合并为单个入口

- 修改日期：2026-11-13（Asia/Shanghai）
- 类型：交互改进
- 适用版本：0.6.11 / 45，版本号不变
- 影响平台：共享 Compose UI，Android、Windows、Linux
- 关联需求：用户截图中的歌曲更多菜单为每个歌单分别显示“加入”或“移出”，要求合并成一个按钮，点开后再选择。

## 需求或问题

歌曲更多菜单直接遍历所有歌单。歌单数量越多，菜单越长，收藏、下一首播放和删除等操作被挤开；截图中的菜单几乎占满手机屏幕。

## 原因与依据

`LibraryShell.TrackRow` 在 `DropdownMenu` 内对 `userPlaylists.forEach` 创建一项加入或移出操作。菜单长度随歌单数量线性增长，缺少独立的选择步骤。

## 具体修改

| 文件 | 关键符号 | 修改与目的 |
| --- | --- | --- |
| [LibraryShell.kt](../../composeApp/src/commonMain/kotlin/com/resonance/player/ui/LibraryShell.kt) | `TrackRow` | 将所有逐歌单菜单项合并为一个“加入歌单…”入口。点击关闭菜单，再打开当前歌曲的歌单选择窗口。所有复用 TrackRow 的歌曲、集合详情和搜索列表同时生效。 |
| [TrackPlaylistDialog.kt](../../composeApp/src/commonMain/kotlin/com/resonance/player/ui/TrackPlaylistDialog.kt) | `TrackPlaylistDialog` | 显示歌曲名称、可滚动的歌单列表、已有归属勾选和歌曲数；支持一次选择多个歌单。点击完成才调用原 `onPlaylistMembershipChange`，只提交本次编辑且与当前归属不同的项；取消、返回或点击窗口外不写入。保留原加入/移出、去重和持久化逻辑。 |

选择窗口复用 `FrostedAlertDialog`，通过已有 `LocalGlassState=null` 隔离独立窗口与宿主 Haze。歌单列表使用 `LazyColumn`、歌单 ID 稳定键和最高 360dp 的滚动区域；歌曲名和操作说明与选项共同滚动，避免短窗口中固定说明挤占选择区域；行使用整行 checkbox 语义及最低 56dp 触摸目标，长歌单名最多两行。没有歌单时显示先新建歌单的说明和关闭按钮，不执行操作。

本地勾选草稿与打开时归属分开保存；确认时仅应用用户实际改变的项，避免把打开窗口后其他流程新增的未编辑归属撤销。关闭窗口先于提交回调，当前歌单被移出而使原歌曲行消失时不依赖该行继续承载窗口。

## 修改前后行为

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 打开歌曲更多菜单 | 每个歌单单独占一行，数量增加时撑长菜单 | 固定一个“加入歌单…”入口 |
| 选择目标 | 菜单内逐项加入/移出，一次操作关闭菜单 | 独立列表显示已有勾选，可选多个，完成后保存 |
| 中途取消 | 操作直接执行 | 取消、返回或点外部不会提交勾选草稿 |
| 许多歌单/长名称 | 更多菜单变长、其他操作被挤出 | 列表独立滚动、按需创建行、长名称换行 |
| 没有歌单 | 更多菜单显示禁用的新建提示 | 点击统一入口可看到空态说明，关闭不修改数据 |

## 平台与数据影响

三端使用同一共享组件；没有改变平台接口。仍由 App 中原 `onPlaylistMembershipChange → persistPlaylists → PersistenceQueue → savePlaylists` 保存关系；加入时保留原推荐音频保留逻辑，移出时保留原队列处理。未修改歌单格式、歌曲 ID、同步包、真实音频和元数据标签，未新增权限、联网请求、模型调用或依赖。版本保持 0.6.11 / 45；没有打包、安装或发布。
