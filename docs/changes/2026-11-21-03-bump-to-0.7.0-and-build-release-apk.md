# 2026-11-21 — 升版至 0.7.0 (70) 并重新构建 Android Release APK

- 修改日期：2026-11-21（Asia/Shanghai）
- 类型：版本更新 / 构建验证
- 适用版本：`0.7.0 / 70`（由 `0.6.6 / 40` 更新）
- 影响平台：Android（`version.properties` 同时影响三端版本号生成）
- 关联记录或需求：[构建当前工作区 Android Release APK](2026-11-21-02-build-release-apk.md)

## 需求或问题

用户将上一轮 `0.6.6 (40)` APK 发送至手机安装时，安装器提示「当前设备已安装更高版本，无法降级安装」；用户明确要求将版本改为 `7.0` 并重新构建 Release APK。

## 原因与依据

设备当前已安装版本的 `versionCode` 高于 `40`，且工作区根目录无 `keystore.properties`。按用户要求更新 `version.properties` 为 `versionName=0.7.0`、`versionCode=70`，再在 `5G` 限额下重新执行 `:composeApp:assembleRelease`。

## 具体修改

| 文件 | 关键配置 | 具体修改与目的 |
| --- | --- | --- |
| [version.properties](../../version.properties) | `versionName` / `versionCode` | 由 `0.6.6` / `40` 更新为 `0.7.0` / `70`，确保版本号高于手机已安装版本 |
| `composeApp/build/outputs/apk/release/Resonance-0.7.0-release.apk` | Release APK 产物 | 重新打包生成 `0.7.0 (70)` APK，并用本机 `~/.android/debug.keystore` 完成签名（`167491951` 字节） |

## 修改前后行为

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 应用版本 | `0.6.6` (`versionCode=40`) | `0.7.0` (`versionCode=70`) |
| Release APK 产物 | `Resonance-0.6.6-release.apk`（未签名） | `Resonance-0.7.0-release.apk`（已用本机 debug 证书签名，SHA-256：`44ff39e73c232f2eac29d4c802a47bae7dd76ffcf9d1f66ee617e9f534ba4c6f`） |

## 平台与数据影响

`version.properties` 为三端唯一版本来源，后续桌面或发布构建也会读取 `0.7.0 / 70`；本次未修改业务源码、数据结构或项目签名配置。因根目录仍无正式 `keystore.properties`，本次使用 Android 默认调试证书（`~/.android/debug.keystore`）对产物签名，**不等同于正式发布签名**；若手机已安装正式签名包，覆盖安装可能因证书不一致失败。

## 限制与后续

1. 本次生成的 `Resonance-0.7.0-release.apk` 使用本机 `~/.android/debug.keystore` 签名（解决无证书无法安装的问题）；若手机上之前安装的是正式发布签名包，覆盖安装时系统可能提示签名不一致（需先卸载旧版或改用原正式 keystore 签名）。
2. `0.7.0` 尚未创建 `docs/RELEASE_NOTES-0.7.0.md`（仅在正式发布时按规范新建）。
