## 原始 TCP/TLS 私有版本

以下说明仅适用于 `server.py`，旧的自定义服务地址/密钥仍支持。

该私有版本是独立的可选组件，需自行配置地址及凭据。它为两个向外连接的设备配对并转发字节；房间原有的证书锁定 TLS、邀请授权和可选设备证书仍在内层，服务器不应收到音频或聊天明文。服务方仍可观察连接源地址、时长和流量；路由摘要与主机的服务访问密钥会到达中继服务。服务不提供匿名性或离线消息。

## 运行方式

需要 Python 3.10+、操作员自行管理的域名与受客户端信任的 TLS 证书。通过安全方式在服务进程环境中设置 `RESONANCE_RELAY_SECRET`：它必须是由安全随机数生成的 32 字节、无填充 Base64URL 表达（43 字符）。不要将真实密钥或证书私钥提交到仓库、命令历史或日志。客户端创建房间的设备需要在一起听设置中填写相同的 HTTPS 主机地址和访问密钥；密钥保存在该设备的系统保护存储中，不包含在邀请中。朋友只需接受邀请。

```text
python server.py --host 127.0.0.1 --port 45901 --cert <证书链路径> --key <私钥路径>
```

默认只监听本机；需跨网络使用时，由维护者自行配置受控的公网监听或四层 TLS 透传、域名与防火墙。客户端地址形如 `https://relay.example.org:45901`：这里的 `https` 表示 TLS 及证书主机名校验，应用协议不是 HTTP，不能直接接入只转发 HTTP 的代理。不要悄悄部署到项目官网或公共基础设施。

进程仅在内存保留等待配对的路由，默认最多 128 连接、32 个等待路由、90 秒等待、180 秒双向总空闲、12 小时及每会话双向合计 4 GiB；可通过命令行参数调整。关闭进程会断开所有房间。该限额不是完整的公网防滥用和计费方案：操作员仍需自行设置网络层访问限制、带宽/流量预算、证书续期及监控，服务器可能在上限处断开长房间。
